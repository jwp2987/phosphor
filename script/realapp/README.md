# script/realapp: real-app and measurement harnesses

These are the scripts that drive a REAL Phosphor build (GUI, real shells, real ssh) and measure it.
They are not run by CI and not by `script/precheck`. They were consolidated from the round-18
working directories (see `docs/testing.md` section 3 for how, when and with which safety rules to
run them). They are research-grade tools: each script carries a header saying what it tests, its
platform, prerequisites and what it restores. Variants were deduplicated to the latest working
version; logs, screenshots, DMGs, zips, binaries and captured data are deliberately NOT here.

## Configuration (no real hosts, users or paths in the repo)

Copy `config.example.sh` to a file OUTSIDE the repo, fill in `PHOSPHOR_BOX_SSH`, `PHOSPHOR_BOX_HOST`,
`PHOSPHOR_MAC_SSH`, `PHOSPHOR_WIN_SSH`, `WINUSER`, `PHOSPHOR_WORK`, `PHOSPHOR_LINUX_RUN`,
`PHOSPHOR_DEB_DIR`, and `source` it. The real values are the owner's local config. Windows scripts
carry an `@WINUSER@` placeholder for the VM profile name; `shared/render.sh FILE` substitutes it.
The Mac scripts run on the Mac, so export the same variables there.

Not included on purpose: ssh keys (`linux/bin/fakesshd.py` needs a throw-away `clientkey`/`hostkey`
you generate with `ssh-keygen` in `$PHOSPHOR_LINUX_RUN/fakessh`), the compiled `htype2` Mac typing
tool and `kseq`/`rec` binaries (build `linux/torture/*.c` with `cc -O2 -lX11 -lXtst`; see also
`script/keylat/`), and any config copied from the owner's profile (tests copy it at run time).

## Rules baked into the scripts (keep them when editing)

Kill only exact PIDs the harness started; back up app data/config with checksums and restore;
box lock `~/perf-remote.lock`; Windows `WINPUSH.lock`; Mac frontmost-app/PID guard before every
key burst; test apps under `dbus-run-session`; never print typed secrets. Details: `docs/testing.md`.
