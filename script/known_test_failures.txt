# Issues #251 and #253 are CLOSED -- the five tests that used to sit here now
# pass, and the list is empty. They were never "open by design"; they asserted
# the oracle's behaviour while this fork implemented three separate defects:
#
#   orphaned subtasks
#       `truncate_from_exchange` only ever rewrote the ROOT task, so rewinding
#       past a `ToolCall::Subagent` left the subtask it spawned in the store.
#       Nothing referenced it, but request construction kept walking it, so the
#       rewound sub-agent silently re-ran. Fixed by
#       `TaskStore::prune_unreachable_subtasks` (BFS from the root over
#       surviving sub-agent calls -- transitive, since a subtask may itself
#       spawn one).
#
#   straddled sub-agent pairs
#       a sub-agent's tool_call and its tool_call_result are written turns
#       apart, so a rewind between them selected exactly one half. The orphan
#       is a malformed request to every provider, and the surviving call kept
#       the subtask reachable. Fixed by `expand_to_whole_subagent_pairs`. This
#       also covered the summarization case, where the effect was a user query
#       that had been deliberately summarized away being dragged back into the
#       next request.
#
#   fork-point tool calls
#       an exact fork can cut between a tool_call and its result.
#       `reconcile_fork_point_tool_calls` now pulls a real result forward when
#       one exists in a dropped turn, and synthesizes a Cancel only when none
#       does -- never for a server tool_call (it would pop an agent off the
#       server's run stack on restore) and never outside the fork-point
#       exchange (pre-existing danglers are history, not damage).

# Issue #441 is fully closed -- all three of its tests now pass, and each turned
# out to be a distinct port omission rather than the single inverted queueing
# predicate the issue hypothesised:
#
#   lrc_queued_prompts_wait_while_subagent_is_active
#       the missing `/compact-and` re-queue (#458). Fixed by porting
#       `execute_queued_compact_and`, measured at 5be073d4f.
#
#   slash_fork_bypasses_prompt_queue_while_in_progress
#       the slash-command data source never subscribed to
#       BlocklistAIHistoryModel, so Availability::ACTIVE_CONVERSATION latched at
#       construction and `/fork` never entered the active command set. It was
#       therefore never detected as a slash command and fell through to the
#       generic prompt path, which queued it. The queueing code was correct all
#       along and never saw a slash command.
#
#   test_classic_tab_completions_close_after_user_backspace
#       `update_tab_completion_menu` lost the pin's `is_user_edit` parameter, so
#       classic completions were exempted from query-invalidation for ALL edits
#       rather than only system-applied ones (cycling). A TODO in the fork
#       described the resulting stale-menu bug.
#
