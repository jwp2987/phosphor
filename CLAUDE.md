# Read these before doing parity work

Skipping any of these means re-deriving something already measured, usually
wrongly. Each exists because a wrong answer cost real time.

| file | why you must read it |
|---|---|
| **`docs/STATE.md`** | **Read this first.** Where the project is right now — parity, guard status, open work, and whether the tree has been verified at all. **Generated by `script/state`; never edit it.** If it disagrees with another document, it is right and the other one has drifted. |
| **`ORACLE.md`** | **The oracle is PINNED, and as of 2026-09-05 it is a source of SUGGESTIONS AND EVIDENCE, not a specification.** Read its "What the pin is for" section before treating any gap as debt: absence is no longer debt, and "differs from Warp" is no longer self-evidently wrong — ~50% of upstream's current work is cloud/account-dependent and rising, and we have now fixed defects that are byte-identical at the pin. Still authoritative for *evidence* ("is this our bug or upstream's?" — `git show <pin>:path` answers it in seconds) and for drift detection. **Take the pin commit from `ORACLE.md`, not from here** — this row has twice named a superseded pin while claiming to point at the authority. |
| **`SCOPE-AI.md`**, **`SCOPE-TERMINAL.md`**, **`SCOPE-REST.md`** | Per-file verdicts for all 854 test-bearing files, with quoted source imports as evidence. The workload is **1,605** tests of real debt — not the 2,239 net gap, and not the discredited "468 missing files". **These three numbers are measured at the OLD pin `02b53fcd8` and have not been re-derived at `42effe840`** (`ORACLE.md` says so explicitly; re-running the classification is next-round work). Quote them for the *shape* they describe — net ≠ workload — and take current numbers from `docs/STATE.md`, which is generated. **Caveat: verdict A is overstated** — MIXED files collapse to their majority bucket, so trace each test's real API dependencies before porting. |
| **`docs/FLEET-ROUND.md`** | How to run a parallel round. Agents do **not** run the full suite; `rustfmt --check` is their gate and the coordinator batches one integration run. Per-agent full-suite runs made the 3-slot build queue the bottleneck. |
| **`HANDOFF.md`** | Current state of `main`, open decisions, and the operational lessons — the cwd trap, exit-status masking, disk exhaustion, "capture before you stop". |
| **`TODO.md`** | The parity ledger. **Verify any entry before acting on it** — four entries have stated the opposite of the code (#148). |
| **`AGENTS.md` §5.6/§5.10/§5.11** | Never weaken a test to go green; fix the code. Every defect gets an issue first. |
| **`docs/pin-migration.md`** | **How to move the pin from N to N+1.** The re-pin tooling already exists (`generate_repin_queue`, `generate_pin_identity_manifest`); this is the runbook that sequences it. Read it before any pin move — its Phase 0 exists because an unfetched oracle makes every re-pin script exit 0 with an empty queue, which reads exactly like 'no work to do'. |
| **`DECLINED.md`** | **Deliberate decisions — both directions.** `SCOPE-*.md` says what is absent; this says what is absent *on purpose*, and since 2026-09-05 also carries an **`IMPROVED`** section for places this fork deliberately does BETTER than the pin. Check it before filing a parity issue, porting a subsystem, **or reconciling a re-pin diff** — an `IMPROVED` entry is expected divergence, not drift to correct. Several entries exist because a gap was filed as debt when it was already a decision. It also lists the common false positives (`computer_use`, `remote_server`, Grok OAuth) that keep getting mislabelled as cloud. |

**Run `script/precheck` before you push.** It runs every gate CI runs except the
full suite, in seconds. CI is the final check, not the one that discovers the
problem — anything CI reports first is a 15-minute round trip you could have had
locally.

Two CI guards enforce what the compiler cannot: `script/check_cloud_boundary`
(no new imports of dropped-cloud modules) and `script/check_stub_coverage` (no
tests against gutted no-op stubs). Read their header comments before changing
them — earlier versions were wrong in instructive ways.
