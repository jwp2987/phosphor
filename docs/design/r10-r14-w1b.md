## Design per case

1. **`agent_basics_powershell`** (Windows PowerShell pane, both modes). Prose, Escape, a shell line, back to the agent, prose again.
   Agent text from `hop=enter_begin buffer=.. input_type=AI`; the shell line from PSReadLine history (exactly one new line) and its
   effect file; the prose nonce must be in neither the history nor the app's pty writes. Rejected: `rec.log` (the pane has none)
   and OCR (none on the VM).
2. **`job_control`** (Wayland, X11, macOS). The OS process state is the oracle for the signal (`ps`: `T` after Ctrl-Z, not `T`
   after `bg`, gone after `fg` + Ctrl-C), with a unique `sleep <n>` so no other process matches; three `jobs` files for the shell's
   own view; `cat` with a line before and a line after the stop for "no key to the wrong program". Rejected: judging from the
   screen, and `sleep 100` literally (another `sleep 100` on the machine would satisfy the check).
3. **`hostile_output_recovers`** (all but the PowerShell pane). A SEEDED 2 MB binary file (same bytes every run, sha in the
   metrics) and `hostile_out.py` (title spam, a 1 MB OSC 8 link, mouse reporting left on, alt screen never left). After each: one
   typed command, exact. ERROR lines are judged against the log before the case (a line the launch already logged is reported,
   not judged); a panic always fails. The main-thread bound is judged on the typing AFTER the output, against the same typing
   before it (software GL frames are over 4 ms by themselves). Rejected: `/dev/urandom` (a failure could not be replayed).
4. **`meta_and_word_keys`** (all five). One command per key, built so a key that does nothing, types a letter or cuts the wrong
   span gives a different line. The raw half uses `bytes_reader.py` (POSIX) or the new `bytes_reader.sh` (Git Bash: the VM's Python
   has no termios). Runs late in a pass (order 96) because Ctrl-A / Ctrl-E show the Linux banner.
5. **`first_run_defaults`** (all five; the Git Bash pane SKIPs: that pane exists only through a setting). Stops the app, moves the
   config directory aside, wipes state, launches with no settings file, judges, then puts the profile back and relaunches.

## Risk

- Test-side only. A wrong expectation shows as a FAIL row on the first run and is a TEST fault to fix; none can pass vacuously
  (each has a control or a check a wrong result trips, and a self-test of its pure parts: `r14_w1b_pure_parts`).
- `first_run_defaults` and `meta_and_word_keys` change what later cases see (a relaunch; the Linux banner), so both run late.
- Expected-bytes table for the Git Bash raw half is from reading (ConPTY and msys re-encode keys); the first Windows run decides.
