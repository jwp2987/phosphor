## Chosen design

- **#2083.** `parse_url_or_existing_path`: a real URL (scheme longer than one letter) parses as before; otherwise a value naming an EXISTING file or
  directory becomes a file URL (relative against the current directory); otherwise the old parse result stands. Kill switch
  `PHOSPHOR_CLI_PATH_ARGS=0`. Rejected: accepting any non-URL as a path (a mistyped subcommand would open a file that does not exist);
  canonicalising (verbatim `\\?\` paths on Windows).
- **T43 `installer_smoke`.** One case, three installers behind one flow (install, launch, second launch, path, control, uninstall, restart). The
  oracle for "joined" and "opened" is the running instance's own `received url` log line plus the second process's exit code; the control arm
  uses the #2083 kill switch so the path check is proven able to fail in the same run. "Uninstall keeps user data" is a sha256 map of the app's
  per-user directories, with a check that a settings file and a database existed. Windows machine state touched by the installer is recorded and
  put back by the case itself (`wininstall.Snapshot`), because the job wrapper restores only part of it (the Explorer context-menu keys are not
  in its backup). Rejected: uninstalling the build under test itself (every later case needs it); a real `dpkg -i` (root, machine change).
- **T44 `upgrade_from_previous_release`.** A resolver (`prev_artifact.py`) that works on all three platforms and prefers a verified download of
  the project's own release asset, then runs the two existing cases as arms. Rejected: a new set of checks (the gap is the input, the spec says
  so); making the machine-local build the first choice (it is whatever was placed there, v0.1.16 today, not the previous release).
- **T46.** The job variable plays the passes. Before any key is typed the pass checks, from the app's job object, that the app runs the shell
  the pass is about; a fallback is a FAIL row of the pass with the cause. cmd.exe gets its own T1 record (`doskey /history`); WSL is a third pass
  that is one SKIP row with the machine change until a distribution exists. Rejected: adding a cmd shell type to the app (owner decision, #2084);
  a routing table for cmd.exe (no corpus rows exist to judge against).

## Risk

- All of it is unrun. The Windows installer arm changes per-user machine state mid-run and relies on its snapshot to put it back; a crash of the
  harness between install and restore leaves the Explorer context menu and the uninstall entry pointing at the job directory until the wrapper's
  own restore (uninstall key, handler, PATH, shortcuts) and the next install.
- macOS: a system prompt for a bundle at a new path would stop the installed copy's launch; the case asks the backend for a dialog after launch.
- The Linux `.deb` arm starts the app through a symlink named `phosphor`, as a real install does; if the app finds its resources by `argv[0]`
  instead of its real path, that is a finding of the test, not a harness fault.
- The download adds a network dependency to the fix tier; without the network the case falls back to the machine-local build and says so.
