## 1. The state machine as it is today

`SubshellSetupState` (view.rs:3169): `Idle | Armed(ArmedSubshellSetup 3111) | Written(WrittenSubshellSetup 3138)`. Alongside it live four older mechanisms that the state does NOT own but that decide holding: `subshell_bootstrap_announced` (22228; "announced" = hold every non-abort key), `subshell_bootstrap_in_flight` (22265; marker-paced remaining lines), `subshell_setup_net` (22284; 10 s notice / 30 s quiet / 120 s ceiling, view.rs:1013-1023), and the 7 s `start_bootstrap_timer` (16149, 24957; 60 s with env vars).

Events and who writes:
- Arm: banner click (`arm_subshell_setup_from_banner` 22935), rc-file hook `SourcedRcFileInSubshell` (19737), auto-warpify at preexec (18806). `arm_subshell_setup` 22901 takes the shape baseline and judges at once (`source=armed`). A Written attempt ignores new triggers (22902).
- Look (`take_subshell_pane_look` 22851, one model lock): block id, cursor position, tail (col 0 → `Tail::None`; else `output_tail_is_input_prompt` on the LAST row of the last 16 grid rows, key_facts.rs:372), alt screen, tty sample (`terminal_attributes::subshell_tty_fact` :765 — Secret = ICANON && !ECHO; Shell leader + !ICANON = LineReader; Shell + ICANON = Cooked; Relay list; `queue_empty` via slave FIONREAD), echo filter facts, marker count. Sampled on: arm, every output wakeup (15729), hand-off change (14673). Never on a timer.
- Armed judge (`judge_armed_subshell_setup` 22954 → pure `subshell_ready::subshell_ready` subshell_ready.rs:125): vetoes in order Gone / 60 s ceiling / Unsupported leader / alt screen / Secret / line_dirty (`handoff.shell_line_may_hold_typed_text`, 36883) / InputPrompt tail / hop. Then: no-probe screen rule (Windows); LineReader → Write if `bytes_since_arm==0 || queue_empty` (182-188, NO tail requirement); Cooked+editor shell → Wait R3; Cooked editor-less → Write(None) only if tail==ShellPrompt (`idle_at_prompt_untouched` 231 or `new_prompt && consumed_behind_prompt`); Relay → Write(trigger) on raw local tty + new prompt + consumed. `last_tty/last_tail/last_position` are recorded on EVERY look, even ones vetoed by alt screen (22983-22985).
- User bytes while Armed: nothing held; `note_user_bytes_for_subshell_readiness` (23247, called only from `write_user_bytes_to_pty_after_paste_stage` 14085) counts bytes, `LineTracker` finds line ends, `on_user_line_ended` (subshell_ready.rs:275) → ReArm (re-baseline from `last_position`, 23318) or Cancel(UserDrove) (23297, auto-warpify aborted).
- Write (`write_armed_subshell_setup` 23016 → `trigger_subshell_bootstrap_now` 16119 → `write_init_subshell_bytes_to_pty` 22173): mints session id, installs echo filter, sets `subshell_bootstrap_announced` (22228) = HOLD starts, writes line 0 as ONE write ` ^K ^U <line0>` (13849-13864) + CR, arms the net (22255), opens `SubshellSetup` (+ `SubshellBootstrapWrite` if more lines) gates (22260/22275, paste_queue.rs:2735-2824), arms the 7 s bootstrap timer (16149). `note_subshell_setup_written` 23082 fills the Written record (baseline, token, secret probe).
- Written: output wakeups → `advance_subshell_bootstrap_on_marker` 22690 writes line N+1 on marker (token,N); `judge_written_subshell_setup` 23118 → `judge_written` (subshell_ready.rs:417): Gone (only before progress), Secret, Question (InputPrompt tail moved since write — checked BEFORE the echo facts), UnsupportedSuspect/Unsupported (R7). Key path: `secret_read_on_key_path_cancels_written_setup` 13954 (termios probe at the key) → cancel+hand back BEFORE the key is offered to gates.
- Probe answer: `InitSubshell` (19704) → unregister probe id, progress, and IMMEDIATELY `trigger_subshell_bootstrap(Some(shell))` (19719) = stage 2 written with no judge, no secret/alt/dirty check (`trigger_subshell_bootstrap` 16103 is now a straight call). `SubshellNotPhosphorizable` (19721 → `end_subshell_setup_unsupported` 22800): releases held keys to the PTY in order (23559 `release_subshell_setup_held_bytes`: announced=None, net=None, state=Idle, close PowerShell gate then SubshellSetup gate).
- InitShell (19759 → `on_subshell_init_shell`), Bootstrapped (19839: progress only), Precmd (19779: `release_held_setup_input_if_subshell_ready` 23548 releases to PTY when announcement no longer applies AND no pending session; `clear_subshell_setup_net_if_setup_over` → Idle). AfterBlockCompleted (18907 `end_subshell_setup_if_block_gone`; 18910 drops only an Armed AutoWarpify).
- Cancel (`cancel_subshell_setup` 23329 / `end_written_subshell_setup` 23388): cuts in-flight lines, unregisters id, R9 flush if `queue_empty==Some(false) && !echo_started`, held keys → `held_keys_destination` (R8): Unsupported+fresh prompt+consumed → PTY (`finish_subshell_bootstrap`+`release…`), else → editor as text (`give_up_setup_gates_to_editor` paste_queue.rs:1365, oldest gate first, count-only toast); Secret → re-arm same trigger (23486).
- Give-up nets: Armed 60 s `PRE_READY_CEILING` → Cancel(TooLong/NotAShell), nothing held. Written: quiet 30 s / ceiling 120 s → `give_up_subshell_setup` 22504 → editor. Abort key during in-flight lines: `abort_in_flight_subshell_setup` 22646 writes ^C now, releases held keys behind it.

Where keys are held/released/handed back: hold = `prepare_subshell_gates` (paste_queue.rs:2791-2817, condition `subshell_bootstrap_announced_age().is_some()` or in-flight lines); release to pty = `close_subshell_setup_gate` 2827 / `settle_subshell_bootstrap_gate` 2848 (called from 23559, 22829, 22684, 23449, Precmd 19820); hand back to editor = `give_up_setup_gates_to_editor` 1365 (from 22572, 23455); PowerShell has its own hold (`PowerShellSetupHold` 3210) not covered here.

## 2. Defects / races, ranked

**D1 — WRITE INTO A PROGRAM (zsh-newuser-install, confirmed by round 8).** Two causes compound. (a) The LineReader row (subshell_ready.rs:182-188) writes with NO shape evidence: `Tail::None` is accepted; termios cannot tell zle from zsh's own `read -k`/`read -q`/`vared`/`select` (all Shell leader, !ICANON). (b) `take_subshell_pane_look` 22858-22868 classifies the LAST ROW of `contents_to_string(false, Some(16))`, not the cursor's row. zsh-newuser-install runs `clear` (`/usr/share/zsh/functions/Newuser/zsh-newuser-install`:402) before the menu, so blank rows sit below the footer; the last fetched row is blank → `output_tail_is_input_prompt` returns false at key_facts.rs:376-378 → tail = ShellPrompt (col>0, visible text somewhere) → LineReader + bytes 0 → `Write`. The setup's `2` of `2>&1` is the menu's "populate ~/.zshrc" key. Trigger: `HOME=<empty> zsh` on Linux, Phosphorize at the menu. Same classifier bug wrong-foots `Question` detection in `judge_written` (23131-23135) and the #1032 callers.

**D2 — WRONG RESULT / 60 s HANG (dash, round 8).** Cooked editor-less rows (189-204) require `tail == ShellPrompt`. dash inherits PS1="" (harness exports it; Phosphor's bash hook sets PS1="" — separate issue), draws nothing → cursor col 0 → `Tail::None` (22858) → `Wait(CookedNoPrompt)` at every look; a user line passes through, runs in dash, its Enter is `ReArm` (Cooked+queue empty, 287) and the next look is "\r\n" at col 0 again. Never written; `subshell_setup_unsupported` hop never logged → `subshell_sh_probe` check at cases.py:2509 fails; ceiling toast after 60 s.

**D3 — WRITE INTO A PROGRAM / SECRET (#1905, open).** Stage 2 goes out at the `InitSubshell` event (19719 → 16114 → 16119) with no look at all: no Secret, alt-screen, line-dirty or InputPrompt veto, no "prompt after the probe's hook" proof. A PROMPT_COMMAND `read -s` (or any rc question after the probe) receives the bash bootstrap lines. The secret checks of #1846/#1854 cover only the Armed judge and Written looks/keys — not this write. `fix/1905-stage2-after-prompt` is empty.

**D4 — MISROUTE / ROOT SHELL LOST (agent mode, round 8, uninvestigated).** The ledger and line tracker are fed ONLY on the pty key path (14085). The agent-footer route (`write_cli_submit_bytes`, dest_table.rs:40 row O-cli-submit, held by H7 gates) never calls `note_user_bytes_for_subshell_readiness`, so `bytes_since_arm` stays 0 → `idle_at_prompt_untouched`/`consumed_by_line_editor` are trivially true → a write can land on a line the user typed through the agent route; and in agent mode a submitted line may be run as a COMMAND of the pane (`pending_command_awaits_precmd` 19834 path) rather than raw bytes into the subshell — consistent with an empty vim file and `exit` reaching the root shell. Needs a log; rank first after D1 if confirmed.

**D5 — STALE FACTS AT A LINE END (key loss by wrong cancel).** `on_user_line_ended` judges with `last_tty/last_tail` of the LAST LOOK (23257-23271). No look happens between keys when the program is silent, so a line typed into a child started after the last look is judged against the shell's facts → `Cancel(UserDrove)` (e.g. `sleep 5⏎` typed at the prompt when the previous look showed Cooked bash with queue non-empty), or a line typed to the shell is judged "program owns tty" (ReArm) when the last look showed a child. Not key-losing, but it kills attempts the user did not cancel and admits ReArms that should cancel. The vim case passes only because the alt-screen look updates `last_tty` to `Other`.

**D6 — HANG (never ready): `exec <shell>` from the parent.** `subshell_tty_fact` returns `LeaderKind::Parent → Unknown` when `pgid == parent_pid` (terminal_attributes.rs:~790). After `exec zsh` the pid is unchanged → every look is Unknown → 60 s cancel. Banner path only; low frequency.

**D7 — WRITE PREFIX INTO A COOKED TTY.** ` ^K ^U` (13857-13862) into a canonical tty: ^K is a literal, ^U kills it — fine for dash at a prompt; but the probe line into a dash `read x` lands in `x`. Termios cannot tell dash's prompt from dash's `read` builtin; only the InputPrompt tail veto guards it. Accept as plain-terminal-equivalent, document.

**D8 — THREE OVERLAPPING TIMERS.** 7 s `start_bootstrap_timer` at every stage write (16149, re-armed on progress 22368), 30 s quiet net, 120 s ceiling; the 7 s one marks the session failed/abandons independently of the net (24985). Not a key-loss path today, but two give-ups for one setup is the #1711-class bug source.

**D9 — R9 flush depends on the echo filter matching.** For a cooked tty the kernel echoes ` ^K^U` as `^K` + ECHOKE erase, not what `expect_setup_line_clear_echo` expects; if the filter misses, `echo_started` stays false and a later cancel may `flush_subshell_tty_input` (23434) while the line is already read — harmless for dash (unsupported ends by event), but a Secret cancel on a cooked shell could flush the user's first password byte. Verify with the dash log (`echo_ended=` in `subshell_written_judged`).

**D10 — Round-8 vim (terminal mode)** is explained by #1904 (build predates 9a131db2c: keys typed after `Bootstrapped` released byte-by-byte). Post-#1904 the terminal-mode path reads correct: rc `sleep` → leader Other → `vim…⏎` ReArm; alt screen Wait; `:wq⏎` ReArm (program_owns_tty); prompt → LineReader Write(None) probe → InitSubshell(bash) → stage 2 → Bootstrapped → Precmd releases the held `echo tok` line. Re-run needed; agent mode is D4.

## 3. Target design

States (one enum owns holding; `announced`/`in_flight`/`net` become fields of it):
- `Idle`
- `Armed{trigger, known_shell: Option<ShellType>, ledger, baselines}` — PASSING (keys go to the pty, ledger fed). 
- `Probe{token, lines, held}` — HOLDING. Stage-1 (`sh` probe, or the known-shell script when `known_shell` is Some).
- `Stage2Pending{shell, hook_position}` — HOLDING (keys stay behind the gate; nothing written). Entered on `InitSubshell`.
- `Stage2{token, lines}` — HOLDING. 
- `Settling` — HOLDING. Entered on `Bootstrapped`, left at `Precmd` (release to pty in order).
- Terminal transitions: `Unsupported` (event) → release to pty, Idle; `Cancel(kind)` → R8 table, Idle; `Secret` while holding → hand back to editor, `Armed{known_shell: Some(shell) if stage 2 was pending}`.

Events: Look (arm / output / hand-off / click), UserBytes(route-agnostic), LineEnd, Marker(token,i), InitSubshell, NotPhosphorizable, InitShell, Bootstrapped, Precmd, BlockCompleted, SecretAtKey, AbortKey, Net(quiet/ceiling), PreReadyCeiling.

ONE readiness predicate `reader_ready(look, ledger, kind)` used for Probe AND Stage2 writes, baseline = arming position (stage 1) or `hook_position` (stage 2):
1. Vetoes unchanged: Gone, Unsupported leader, alt screen, Secret, line_dirty, InputPrompt tail (classified on the CURSOR ROW), hop.
2. LineReader (Shell leader, raw): REQUIRE `tail == ShellPrompt` drawn since baseline AND (`bytes_since_arm==0` OR `queue_empty`). `Tail::None` → `Wait(NoPrompt)`. (Fixes D1; a line editor with empty PS1 is the accepted loss — it has no visible proof.)
3. Cooked editor-less Shell leader: NO prompt required. Write(None) iff `queue_empty==Some(true)` AND `tail != InputPrompt` AND (`bytes_since_arm==0` OR the look is after the last line end with the shell still the leader). Optional Linux strengthening, same look, one `/proc/<pgid>/syscall` read: leader blocked in `read(2)` on the tty fd = "reader idle" fact (R10-compatible; no timer). (Fixes D2.)
4. Cooked Shell with editor: Wait (R3). Relay: unchanged. Other/Parent/Unreadable: Wait; Parent additionally re-reads comm of `parent_pid` and treats a changed comm as a Shell leader (D6).
5. Stage 2: `Stage2Pending` is judged on every look with the same predicate (shell type = the probe's answer, LineReader expected); a Secret/InputPrompt look → hand back + `Armed{known_shell}`; ready → write stage 2 (#1905 decision: a prompt after the probe's hook).

Invariants: (I1) a byte is held iff state ∈ {Probe, Stage2Pending, Stage2, Settling}; the passing→holding edge happens inside the write call, same event turn, so no byte is between. (I2) every user byte toward the pty, from any route (pty key path, agent footer submit, queue delivery), enters `on_user_bytes_toward_pty` which feeds the ledger (passing states) or the gate (holding states) — D4. (I3) nothing is written except on a Look that returned Write, or on a Marker for the next line of the same token. (I4) a Secret look/key in any holding state hands back to the editor first, then re-arms. (I5) held keys go to the pty only on an event that proves a reader at a prompt (NotPhosphorizable, Precmd, R8 Unsupported); every timer hands back to the editor. (I6) the line-end verdict uses facts sampled AT the key (termios + tcgetpgrp are cheap; take them on the key path like `secret_probe`), not the last look (D5). (I7) one net per setup: PRE_READY_CEILING (passing states), quiet/ceiling (holding states); the 7 s bootstrap timer is not armed for subshell setups (D8).

Minimal change sequence from today's code:
1. `take_subshell_pane_look` (22851): classify rows `..=cursor.row` (pass the cursor row to `output_tail_is_input_prompt`). Pure, no state change. Fixes zsh (D1b).
2. subshell_ready.rs LineReader row: add `tail == ShellPrompt && prompt_moved_since_baseline` (else `Wait(NoPrompt)` new `WaitWhy`). Fixes D1a.
3. subshell_ready.rs Cooked editor-less rows: drop the tail requirement (keep the InputPrompt veto and `queue_empty`, leader Shell). Fixes D2.

Stage 2 gating: replace 19719's direct call with `self.subshell_setup_state = Stage2Pending{shell, hook_position}` (or a flag on `Written`), judge it in `judge_subshell_setup_on_event`, write via `trigger_subshell_bootstrap_now` on Write; Secret → `end_written_subshell_setup(Secret)` with `trigger.shell_type = Some(shell)`. Fixes D3/#1905.
5. Line-end facts at the key: in `note_user_bytes_for_subshell_readiness`, sample `model.secret_read_probe()`-style termios + `tcgetpgrp` through the existing probe (no model lock needed if the probe fd is shared like `secret_probe`); fall back to `last_tty`. Fixes D5.

## Addendum: b288984a5 (#1905 "stage 2 waits for a prompt drawn after the marker") checked against the design

What b288984a5 added (diff 5c24c76fc..b288984a5): `SubshellBootstrapInFlight.after_prompt` (view.rs:~3038), `SubshellPaneLook.text_since_marker` (~3210, model `text_since_setup_marker`), and a gate inside `advance_subshell_bootstrap_on_marker` (~22706-22731) that writes line N+1 only when `subshell_ready::stage_two_may_follow(tail, echo_mid_line, text_since_marker, tty)` (subshell_ready.rs:~457-475) says a ShellPrompt tail was drawn after line N's marker and the tty is not Secret / not a cooked line-editor shell.

Verdict vs the design:
1. PARTIAL for D3/#1905. The gate paces lines WITHIN a marker-paced stage. The stage-2 FIRST line is still written at the `InitSubshell` event with no look: view.rs:19719 `self.trigger_subshell_bootstrap(Some(shell_type), false, ctx)` → 16114 → 16119 → `write_init_subshell_bytes_to_pty`, which writes ` ^K ^U <bash line 0>` + CR immediately (22243-22248). A `PROMPT_COMMAND`/rc `read -s` that opens between the probe's hook and the next prompt still receives stage-2 line 0 (the exact #1905 shape). The design's `Stage2Pending` state (judge on every look, baseline = position at the hook, Secret → hand back + re-arm with `known_shell`) is still needed; the smallest form: in the `InitSubshell` handler set `in_flight`-style pending state and let `judge_subshell_setup_on_event` call `trigger_subshell_bootstrap_now` when `stage_two_may_follow` holds for a look whose position moved past the hook's.
2. `stage_two_may_follow` reuses `look.tail`, which comes from `take_subshell_pane_look` classifying the LAST fetched grid row (22858-22868) — defect D1b applies to it too: after a `clear` the footer/prompt row is not the row examined. Fix D1b first (cursor-row classification); the #1905 gate then inherits it.
3. `stage_two_may_follow` returns true for `Unknown` and `Relay` without a `queue_empty`/raw-tty check — consistent with the owner's "no OS fact exists" note, but note it also returns true for `LeaderKind::Other` (vim/fzf in front shows as `Unknown` kind): a stage-2 line after a marker would go into a program the rc started if that program draws an unterminated non-prompt line. Low probability (the program must start between two setup lines), but the design's rule "Other leader → Wait" should be applied here as well (`tty.leader == LeaderKind::Other → false`).
4. `stage_two_may_follow` requires `tail == ShellPrompt`, so an editor-less shell with empty PS1 (D2) would also stall its probe's line 1 forever (only the quiet net ends it, 30 s, hand-back). With D2's rule (cooked editor-less: queue_empty instead of a prompt) the probe path must get the same relaxation: `Cooked && !leader_has_line_editor → tty.queue_empty == Some(true)` rather than a prompt. This directly affects `subshell_sh_probe` on the harness (PS1="" inherited): today at b288984a5 the probe would be written (if D2 fixed) but line 1 would then wait for a prompt dash never draws.
5. Everything else in the review stands unchanged at b288984a5 (D1a LineReader needs a prompt, D4 agent route ledger, D5 line-end facts at the key, D6 Parent leader, D8 three timers, D9 echo filter on cooked ttys).

Suggested commit order for the implementing agent (each with its own GitLab issue, labels v0.1.18 found-overnight): (1) cursor-row tail classification + unit test; (2) LineReader requires ShellPrompt + truth rows; (3) cooked editor-less rows drop the prompt requirement, probe pacing uses queue_empty for them + truth rows + view test with PS1=""; (4) Stage2Pending gating of the stage-2 first line + view tests (Secret after hook → hand back + re-arm; prompt after hook → one write); (5) `Other` leader veto in `stage_two_may_follow`; (6) agent-route ledger/gates (after a log confirms D4); (7) line-end facts sampled at the key; (8) stop arming the 7 s bootstrap timer for subshell setups. appci cases for (1)-(4) already exist (zsh_newuser_install, sh_probe, secret_after_prompt, vim_typeahead) — add a PS1="" leg to sh_probe and a first-PROMPT_COMMAND `read -s` variant to secret_after_prompt in cases.PROVING, and update docs/testing.md.
