# Secrets and privacy review (Fable 5.2, 2026-11-09)

Read-only review at merge/w0.

## Round 8 `agent_interactive_password` — explained, it IS an app leak (top priority)

Data path: the hand-over for `read -s` is `switch_control_to_user(BlockedOnInput)` (app/src/ai/blocklist/block/cli_controller.rs:736). When the command finishes and control returns to the agent, cli_controller.rs:838-859 builds `resume_context = block_context_from_terminal_model(&terminal_model, &block_id, false)` and passes it to `controller.resume_conversation(..)` (app/src/ai/blocklist/controller.rs:3373). That context (app/src/ai/blocklist/context_model.rs:549-570: `command`, `output = block.output_grid().content_summary(5000, 5000, false)`, exit code; redaction only if the user's toggle is ON — owner's is OFF) is rendered into the USER message's `<attached_context>` block (app/src/ai/agent_providers/user_context.rs:23-140, `AIAgentContext::Block`). The command prints `got:<secret>`, so the secret rides in a user-role message of request 2 in addition to the tool result — exactly what the judge (script/realapp/appci/cases_agent_interactive.py:44-52) flags. Same on macOS and Wayland because the path is platform-independent. Note the wider rule: for ANY hand-over, whatever the program echoed (a mistyped password at a visible prompt, a token the program prints) is re-sent as user prose, bypassing the tool-result channel. Tell the fix/r8-agent-cases Sonnet agent: this is the cause.

Minimal fix: in cli_controller.rs:838-859 do not attach the block when it is the agent's own action (`action_id.is_some()` — its output already returns as the tool result), or at least when the take-over reason was `BlockedOnInput`. Pass `Vec::new()` as `additional_context`.
Test: unit in cli_controller tests — hand-back after `BlockedOnInput` calls `resume_conversation` with empty `additional_context`; appci `agent_interactive_password` (fix tier) already pins it. docs/testing.md row for #1882 cluster.

## Ranked findings

1. (model) Round-8 hand-back block attachment — above.

2. (model) Typed lines reach a BYOP model while the tty reads a secret — YES, two routes, both unredacted with redaction OFF:
   a. NLD predict: app/src/terminal/input.rs:10319-10331 fires on every edit when `FeatureFlag::PredictAMQueries` + `natural_language_autosuggestions` + `is_ai_input_enabled()` (true in autodetect's UNLOCKED guess) → input.rs:16462-16495 sends `editor.buffer_text()` as `partial_query` plus the last block's command via `active_ai::nld_predict::dispatch` (app/src/ai/agent_providers/active_ai/mod.rs:180-205) to the provider. No `tty_reading_secret()` check anywhere on this path. Trigger: autodetect on, a `sudo`/`read -s` is up, keys land in the editor (the #1883/OD-4 situations, or typing before the hand-off resolves) → partial password debounced to the provider.
   b. Next-command suggestions: app/src/ai/predict/next_command_model.rs:347-385 ships `recent_blocks` (`command`, `output_summary`, active_ai/mod.rs:84-89) after every block; a password typed at a visible prompt by mistake becomes a block command and is sent.
   Fix: gate (a) with `!model.tty_reading_secret()` and require the input type be LOCKED AI (not autodetect's guess) for `partial_query`; for (b) skip blocks whose command ran with exit code 127/not-found or whose command was typed while `tty_reading_secret()` (record the flag on the block), and apply `outbound_redaction::redact_chat_request` unconditionally for these fire-and-forget one-shots (owner decision). Test: view_test with the secret probe installed true — editing the buffer never sends on `debounce_ai_query_prediction_tx`; unit on the new predicate.

3. (network: key to another origin) Provider key/custom auth headers survive a cross-origin redirect to any OTHER configured origin. BYOP client: app/src/ai/agent_providers/chat_stream.rs:6073-6080 `RedirectGuard` → `Gate::check_redirect` (crates/network_gate/src/lib.rs:439-468). `AI_ENDPOINT` is `Kind::Automatic` (lib.rs:733-736), so a hop is allowed to ANY configured origin: every provider's base_url, the models.dev URL, the proxy (app/src/settings/init.rs:424-443). lib/rust-genai/src/client/web_config.rs:170-178 then `attempt.follow()`; reqwest strips only Authorization/Cookie/Proxy-Authorization cross-host, so Anthropic `x-api-key` (lib/rust-genai/src/adapter/adapters/anthropic/adapter_shared.rs:500,722), Azure `api-key`, and the user's `extra_headers` ("Values may contain secrets", oneshot.rs:44-46, forwarded :141-144) go to the redirect target. Trigger: provider/gateway B 30x → provider A host. Violates "key only to its own provider origin". Fix: for `AI_ENDPOINT` (and `http_client::Client::for_purpose(AI_ENDPOINT)` used by embeddings) require the hop host:port == the first URL's (`attempt.previous()[0]`) — add an `initial_origin` to `RedirectGuard`/`redirect_policy`; otherwise `stop()`. Test: crates/network_gate/src/lib_tests.rs — two configured origins, redirect A→B under AI_ENDPOINT denied; genai web_config test — cross-host hop stops.

4. (logs/model) Exa key in the URL: app/src/ai/agent_providers/tools/exa.rs:4,25 `?exaApiKey=…`. reqwest error `Display` embeds the URL; tool errors return to the model as tool results, and outbound redaction explicitly excludes fetch URLs (outbound_redaction.rs:24-26). Fix: redact the query in every error string (strip `exaApiKey` before `anyhow!`), or move to a header if Exa accepts one. Test: unit — a failing call's error text contains no key.

5. (logs: hosts) Owner rule "no hosts in logs" is broken by: chat_stream.rs:5995-5998 `[byop] build_client … endpoint_url=scheme://host:port` (`redact_endpoint_for_log` :3465 keeps the host), openai_compatible.rs:147,168,204,232 `[provider-fetch] GET {url}` (full user URL). Fix: log `network_gate::hash_host(host)` like hop lines. Test: unit on `redact_endpoint_for_log` returning a hash, no host substring.

6. (disk/other process) MCP: env values stored plaintext in sqlite (`mcp_environment_variables.environment_variables TEXT`, crates/persistence/migrations/*/up.sql); managed secrets rendered into variable values (app/src/ai/mcp/templatable_installation.rs:113-145) may be placed in `args` → `cmd.args(args)` (app/src/ai/mcp/templatable_manager/native.rs:1905) = secret in argv (#1864 class). Fix: refuse `{{secret}}` substitution into args (env only), warn; consider secure_storage for env values. Test: unit — templated arg keeps placeholder / errors.

7. (disk, low) Linux secure-storage file fallback uses a hardcoded AES-256-GCM key (crates/warpui_extras/src/secure_storage/linux.rs:150); 0600/0700 files. Obfuscation only. Fix: derive from a random per-user key file (0600) with migration; document. Test: round-trip with new key file.
