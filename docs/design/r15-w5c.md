## 1. T47: the real privilege boundary (F4)

Cases: `sudo_su_real_shell`, `subshell_ready_relay_shape`, `subshell_ready_docker_t_without_i`.

Cause of "SKIP everywhere":

- `cases_coverage_a.py:360` and `cases_subshell_ready.py:435` (line numbers at `integ/r14` 75847d84c) ran only when `sudo -n true` succeeded, that is passwordless ROOT sudo for the CI user. No test machine has it, and it is more than the cases need: the boundary is "another uid behind sudo".
- `cases_coverage_a.py:364-380`: every arm called `r.unverifiable` when it could not run. ksu calls it on both branches (lines 378 and 380), so the row was NOREF on every machine even with a perfect sudo arm. The case could not pass anywhere.
- `cases_subshell_ready.py:447` typed `>> ~/w/lab_relay.txt` inside the sudo shell. With `env_reset` (sudo's default; Ubuntu kept the caller's HOME only until 19.10) HOME there is the target's home, so on a current machine the file would have been `/root/w/...` and the case would have failed its first run.
- `leave_inner()` proves the root shell by a PID probe written to `~/.appci_pid`. Behind sudo `~` is the target's home, the probe finds nothing, and the case would have failed "the shell in front after leaving is the pane's ROOT shell (got none)".

Fix (`appci/priv_boundary.py`, new; the three cases call it):

- `sudo_target()`: the user named by `APPCI_SUDO_USER` (environment or the machine-local `ci.env`) when `sudo -n -u <user> true` works, else root when `sudo -n true` works. A target with the CI user's own uid is refused.
- `shared_dir()`: where the inner shell writes. Root: the work dir. Another user: a 0777 directory in the work dir when every parent lets others through, else under `/var/tmp`; removed afterwards.
- Relay case: `sudo -s` for root as written, `sudo -n -H -u <user> -s` for a test user (both match the app's sudo subshell regex, `warpify/settings.rs:378`; the self-test checks that). The effect file is an absolute path. The shell is left with `exit_nested()` (shell-count proof), then `leave_inner()` proves the root shell.
- `sudo_su_real_shell`: arms that cannot run are `NOT RUN:` notes and the metrics `boundaries_run` / `boundaries_not_run`; the verdict is the arms that ran. su also runs through passwordless root sudo.
- Docker: `docker_ready()` tells apart "not installed", "daemon not usable by the CI user" and "image absent".
- Each skip carries `NEEDS:` with the exact commands (section in `docs/testing.md`).

Rejected:

- Having the harness create the user or the sudoers entry. Machine changes are the owner's.
- Keeping root as the only target. It forces a broader machine change than the test needs.
- podman or another image. The app's subshell regex and the profile's added command name `docker run --rm -t alpine`; widening them is a different change.

Risk: these have never run. The banner for `sudo -n -H -u <user> -s`, the relay judge's samples for a non-root target and `exit_nested()` behind sudo are read from code, not seen. The first run on a machine with the test user decides.

Owner decision needed: the NOREF to `NOT RUN:` change loosens a row. It is in the commit message and the report.

## 2. T48: `gpu_real_render` (new)

Fact: the app already logs which adapter a window uses: `Surface configured: backend=.. adapter=".." .. software_renderer=..` (`resources.rs:1029`, logged at `resources.rs:129`). No committed run kept the app log, so which adapter the box's Wayland job uses is not known from the results.

Design: two launches on one profile, default and forced software (`WGPU_BACKEND=gl LIBGL_ALWAYS_SOFTWARE=1`; `mod.rs:141` reads `WGPU_BACKEND`). Same drawn screen in both. Judged: the adapters, the GPU launch's own share of a frame (`hop=frame_drawn`: total less acquire less present) against 4 ms p50 and 16 ms p95, and the two screenshots within 2 % with a control pair that must differ by 5x that.

The frame figure excludes the swapchain wait and the present call on purpose: the first is the compositor's pace, the second blocks on vsync under GL. What is left is the scene build, encode and submit, which is what the owner's 4 ms UI budget is about.

SKIP with `NEEDS:`: no render node; a node the CI user cannot open; a node but no hardware adapter the session can present to (Xvfb). FAIL: a presentable hardware adapter listed and a software one used.

Not built: "a lost device recovers". The harness cannot take a device away without root, and the app has no hook. Adding a renderer test hook is app code on the draw path that could not be compiled or proven here; I left it out and the case says `NOT RUN:` with what it needs on every row. `draw_retry_tests.rs` covers the policy.

App change: none. One unit test pins the wording of the `Surface configured:` line (`resources_tests.rs`).

Risk: the budgets are first guesses for this GPU and have never been measured; the 2 % picture tolerance likewise (anything time-dependent in the block list would show). Both are knobs. A software EGL client under headless sway is expected to work but is unproven; if it does not come up the row is NOREF with the reason.

## 3. T49: soak on macOS and Windows

Cause: `cases_robust.py` `proc_set` / `sample` read `/proc`; macOS read one process through `MacApp.cpu_ticks` and then SKIPPED for want of a close key; Windows was `NOT_WINDOWS` ("samples /proc").

Fix (`appci/procsample.py`, new): one `sample(ctx)` for the three platforms (pids, memory KiB, CPU seconds). Linux figures unchanged. macOS: `ps` over the job's bundle. Windows: the app's job for the pids, the Win32 counters for the processes running the app's exe, private bytes as the memory figure; `Get-Process` by exe path as the fallback. A sampler control was added: the first reading must contain the main pid and be at least 20 MB, and more than 3 missed minutes fail.

Tiers: 10 minutes in the fix tier on macOS and Windows only (two of the four Windows passes), 60 elsewhere. A run under 18 minutes samples memory twice a minute so the growth rule still gives a verdict.

macOS close: Ctrl-D, proven by the tab shell's pid going away; then the palette close; else fail and stop with `NEEDS:` a close chord (T32, sibling branch `fix/r15-w4mac`). When that branch gives the backend a close key and `APPCI_KEY_CLOSE` is set, the key is used and this path is not taken.

Rejected: `FIX_ONLY_IN["soak"]` in `winmap.py` to limit the Windows passes. The self-test requires every PROVING case in every Windows pass's plan, so the case skips itself with a reason in the other two.

Risk: Ctrl-D in an agent-mode tab on macOS is unverified; the Windows flood through ConPTY may need more than the 90 s given to the sentinel. Cost: about 13 minutes per soaked pass (macOS 2, Windows 2).

## 4. #2071: `agent_code_recycle`

Causes of F10, two:

- the answer came from the CI model (`cases_caseagent.py:957-967` at `integ/r14`), and three of the case's skips blamed the model;
- the token was `ctx.tok(4).upper()` (line 952), for example `T12_ABCD`. `visible_snippets()` searches the screen text after `_squash()` removes everything but letters and digits, for `rcy<tok>NN` with the token's underscore still in the pattern. It can never match. With an OCR engine the case therefore always read "none of the snippets is on screen" and skipped as "model nondeterminism", whatever the model wrote.

Fix: a fake-model trigger ("Please write code snippets TOK count N" gives N fenced blocks), the case agent-only and in `PROVING_FAKE`, a letters-only token, and no skip left except "the pass's provider is not the fake" (`NEEDS:`). A prompt that did not reach the model, or an answer that is not on screen, now fails.

Cost of agent-only: the terminal-mode arm is gone. It never produced a verdict, the scripted model has an agent pass only, and the recycling is the block list's and has no mode. If the owner wants a terminal-mode arm it needs a terminal fake pass in `run.py`.
