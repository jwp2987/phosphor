## T41: no network at start, without strace

**Cause of the gap.** `cases_netless.py:76` skipped everything that is not Linux; the oracle was `strace -f`.

**Chosen.** A poll of the operating system's own per-process connection table, every 0.25 s, from before the
launch until the scripted session ends (`nettrace.ConnPoller`):

- macOS: `lsof -nP -i -a -p <pids>`; the pids are every process whose executable is inside the job's bundle
  plus their descendants (`ps -axo pid=,ppid=`).
- Windows: `netstat -ano`; the pids are the members of the app's job object (`winapi.job_pids`), or the app pid
  and its descendants when there is no job.

A row counts when its remote address is not loopback, not unspecified and not in the session allowlist. The
judgement is the Linux one: nothing at all during launch and idle; during the scripted session only the
configured model endpoint.

**Control (a wrong tool fails here, not in the verdict).** Before the app is relaunched, a child process of the
harness connects to a listener on this machine's own non-loopback address and holds the connection. The poller
must list that connection for that pid. If it does not, the case SKIPs with `NEEDS:` and the exact command that
has to work. A machine with no non-loopback address also SKIPs with `NEEDS:` (nothing to prove the tool with).

**What the poll cannot see, said in the result.** A connection that opens and closes between two polls, a UDP
datagram sent without `connect()`, and DNS (the resolver service makes the query, not the app). The Linux trace
sees all three. The case records `trace=poll` and a note; it is weaker evidence than Linux and says so.

**Rejected.** A `pf` anchor on macOS and a firewall rule on Windows: both need root or an elevated runner, which
is a machine change; `nettop`: its per-process rows are flows that exist at sample time, the same limit as `lsof`,
with a less stable output format; a deny sandbox around the whole app (`sandbox-exec`): it changes what the app
does instead of observing it, and a refused connect does not show what was attempted.

## G8: the other Linux-only safety cases

- `network_gate_switch`: the launch-log half needs only a relaunch on a rewritten settings file, which every app
  handle has. The page half needs the settings key, the palette and the app's own settings file; on macOS and
  Windows the app's file is not the profile's file, so `cases_robust.live_settings_file` names it. Windows: one
  pane is enough (nothing depends on the shell); the Windows settings key (`ctrl+comma`) has never been played,
  so a missing page hop is reported as not judged there, not as a failure.
- `claude_plugin_offline`, `agent_plugins_offline`: the only Linux-only part was `unshare -rn`. macOS has
  `sandbox-exec -p '(version 1)(allow default)(deny network*)'`. New on every platform: the prefix is proven to
  block (a connect to a loopback listener made inside it must fail) before "works offline" is claimed. Windows:
  not built. The Claude and Gemini plugins ship bash hooks only; the Codex plugin has PowerShell hooks, and running
  those offline needs a per-process network block (elevated) and a console capture the harness does not have.
  `winmap` says so with `NEEDS:`.
- `keyring_unavailable_startup`: Linux only by nature (D-Bus Secret Service). macOS has T42. Windows keeps secrets
  in DPAPI-protected files; there is no service that can be absent.
- `agent_gate_deny_allow`, `network_gate_notice`: need the pointer and OCR (macOS: T32; Windows: T31).
  `agent_gate_off_live`, `agent_gate_key_never_leaves`: not ported in this wave (they lean on the Linux close key
  and the strace oracle in six places). Their skip text now names what is missing instead of "(this platform)".

## T42: macOS keychain at start (#1977)

The app is started with a private `HOME`. Whether the Security framework follows `HOME` for the keychain search
list is the fact everything depends on, so the case proves it first without changing anything: a keychain created
by `security create-keychain` with a relative name must land under the private `HOME`. If it lands under the
runner's real home it is deleted and the case SKIPs with `NEEDS:`. The runner's own `security default-keychain`
and `list-keychains` are read before and after every step; a difference fails the case and is put back.

Arms, one launch each: `none` (no default keychain), `unlocked` (the test keychain is the default, unlocked),
`locked` (the same, locked).

- every arm: first frame within `APPCI_KEYCHAIN_FIRST_FRAME_MAX_MS` (2000), typing exact after the first prompt,
  no `Failed to read ... from secure storage` ERROR;
- `none`: exactly one `The default keychain could not be opened` line and one keyring notice;
- `unlocked`, `locked`: no such line, no notice;
- `locked`: unlock prompts are counted (windows of the `SecurityAgent` process, through System Events) and each is
  cancelled. More than one is a failure. If System Events cannot count windows (no Accessibility permission) the
  arm is not played and the case is not judged (`NEEDS:`), because a prompt nobody can dismiss would block every
  later case.

**Risk.** The first run is the first time any of this meets a Mac. The `finally` block stops the app (which
withdraws a pending prompt), deletes the test keychain and relaunches.

## T45: keybinding_rebind

`keybindings.yaml` is read at launch only (`app/src/keyboard.rs:38`), so each arm is a relaunch.

- Arm A: `workspace:new_tab` on `ctrl-shift-f8`. The new chord opens a tab; the default chord does not.
- Arm B: `workspace:show_command_search` on `ctrl-shift-f9` and `workspace:new_tab` on `ctrl-r`. Ctrl-R opens a
  tab and opens no command search; the moved chord opens command search.
- The file is byte-identical after each launch (the app must not rewrite it), and is restored at the end.

Oracle: the tab count from `hop=tab_activate` (every platform), the prompt log where the pane has one, and the
`keydown_keybound ... action_type=` line where the key goes through the keymap.

F8 and F9 because every letter chord is taken by a default. The macOS backend gets F-key codes.

**Not decided here.** A user file that puts a second action on Ctrl-R *without* moving command search: the
focused input's binding answers first (`crates/warpui_core/src/core/app.rs:2462`, child before parent), so command
search still opens. Whether the user's line should win is an owner question next to #1988; the case does not
play that arm.

## T50: editor_daily, and two app defects found while building it

**#2088, no keyboard path to Replace.** `app/src/code/editor/find/view.rs`: `ToggleReplaceOpen` and `ReplaceAll`
are dispatched from `on_click` only. Fix: two editable bindings in the find bar's context,
`find:toggle_replace` (`alt-cmdorctrl-r`, focus moves to the replace field) and `find:replace_all`
(`alt-cmdorctrl-enter`). Off switch: `none` in `keybindings.yaml`. The click keeps its behaviour (a separate
action). Rejected: Ctrl-H (the single-line editors bind it to backspace and answer first), Cmd-Option-F (bound to
fold in the same editors).

**#2087, a disk change under unsaved edits is not flagged.** `global_buffer_model.rs` refuses the update and
emits `success: false`; `local_code_editor.rs:1719` draws the banner only when two versions differ, and a refused
update changes neither. Fix: the model remembers the file (`disk_changed_under_edits`) unless the reported text
is what this editor's own last save wrote (a hash, so no second copy of the file), and the banner condition reads
it. Cleared by a save, a reload, a discard. A reload the user types over before it lands is the same state.
Kill switch `PHOSPHOR_EDITOR_DISK_CONFLICT=0`. Trace line `editor_disk outcome=<reloaded|conflict>
external=<bool>` (target `editor_disk`, debug), format pinned by a unit test.

Rejected: a new event variant (four exhaustive matches to touch, nothing gained); flagging every refused update
(the echo of each save while the user keeps typing would flash the banner); a disk check inside `save`
(`FileModel::save` is documented as unguarded for a live buffer; a guard needs the old text or a read on the
save path, and #1340 is about this editor's memory).

**Left open.** Ctrl-S in the moment before the watcher has reported the change still overwrites (watcher debounce
200 ms). The case does not play that race. Ctrl-S while the banner shows is the banner's Overwrite: the case
records what the disk holds afterwards and does not judge the choice.

**The case.** Find and replace by keyboard on a file with multi-byte text before the matches and near-miss words:
one Enter replaces exactly one match, the replace-all key the rest, bytes exact. Close with unsaved edits: the
close key asks, Escape keeps the edits (a save then has them), close and Enter discards (disk unchanged). External
change: clean buffer is reloaded (a token typed and saved lands on the new text); dirty buffer is flagged and the
disk is left alone.
