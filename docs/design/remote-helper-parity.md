# Wave H parity: small helper + no-helper shell backend (design, condensed; coordinator-reviewed 2026-11-09)

Owner: the small `phosphor-remote` helper does EVERYTHING the old full-app server did; the same features work WITHOUT a helper over the ssh session. GitHub stays (other users). Indexing: no HTTP/TLS in the helper (see g). Timer rule: event-driven only; no debounce, no polling; a timer may only be a give-up net that hands back or exits.

## Coordinator rulings on the design
- R1 SHELL BACKEND CHANNEL: the shell backend must NEVER type into the user's pty (no in-band PTY executor for these features). It runs only over an out-of-band channel: the ControlMaster side exec / the persistent side shell from the owner's plan. If no out-of-band channel exists for a session, the feature is unavailable there (say so in the UI), never in-band.
- R2 Git push/pull/PR credentials: fail fast (`GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=` unset, `SSH_ASKPASS_REQUIRE=never`, `-o BatchMode=yes` via GIT_SSH_COMMAND) and show stderr; offer a "Run in terminal" button that puts the equivalent command into the user's input editor (NOT executed) so the user runs it with their own askpass/agent. (OWNER CONFIRMED 2026-11-09.)
- R3 Bundled skills: never embedded in the helper; the app supplies its own bundled skills; the helper/shell report only host skills + rules. (OWNER CONFIRMED 2026-11-09.)
- R4 Shell-arm buffers: conflict detection at save (mtime/size/sha256 check), no live push. (OWNER CONFIRMED 2026-11-09.)
- R5 inotify cap / ENOSPC / NFS: repo marked "unwatched", falls back to the shell arm's refresh events; logged.

## 1. Shared abstraction (P0)
- `remote_server::backend` (feature `client`): `trait RemoteFeatures` with async methods per family taking/returning the EXISTING proto types. Backends: `HelperBackend(Arc<RemoteServerClient>)` pass-through; `ShellBackend` (out-of-band executor + ShellKind {Posix, Fish, Nu, Pwsh}; non-POSIX login shells wrap `sh -c '…'`; pwsh builders for Windows hosts).
- `remote_server::shellcmd` (no feature, no I/O, no warpui): pure command builders + parsers shared by the shell backend AND the helper's git code (identical argv and parsing).
- `FeatureRouter::backend(session, Family)` = the ONE decision point, next to RemoteServerManager. Family→capability const. Helper connected && supports(cap) (empty list = legacy = all) → HelperBackend; else ShellBackend. UNSUPPORTED or connection lost → next call uses shell. Call sites never retry themselves. Replace ad-hoc gates at `manager.rs:1843/:1939`. Per-family override setting "always shell" (tests, lab arms).
- `RefreshCoordinator` (per session+repo) consumes `RemoteRefreshEvent::{Precmd{session,cwd,last_cmd}, CwdChanged, UserAction(Refresh), AfterOwnWrite}`; one in flight + a `dirty` flag (no timer); skip via `command_may_change_head/_cwd`.
- Shell output envelope: sentinel/length-framed sections + `exit=N`; binary via `base64 -w0`/`base64`/`openssl base64`/`od -An -tx1` (probed once per host via `command -v`, cached); 10 MB cap per call (= MAX_DIFF_READ_BYTES).
- Chip: "limited: no remote helper" → wording "shell mode"; helper optional.
- P0 also reserves stub modules + match arms in `daemon/server.rs`/`mod.rs` (returning UNSUPPORTED) and ALL new capability consts, so later packages only fill their own files.

## g) REVISED (owner split) — replaces the g row above
- Helper (or app over shell) lists/reads/chunks/hashes on the host and keeps the store on the host: fragments content_hash→{path,start_line,end_line,byte_start,byte_end}, file manifest + root hash, vectors as a flat f32 file keyed by content_hash + embedding_storage_key. Flat file, no sqlite. Brute-force cosine search (pure Rust).
- EmbeddingProviderConfig is NO LONGER sent to the host (reserve its proto fields, ignore them). The key never leaves the user's machine.
- Additive proto: ScanCodebase{repo_path} → manifest {path,file_hash} + chunk hashes (streamed via FrameChunk :245); GetChunks{repo_path, content_hashes} → text only for hashes without a vector; StoreVectors{repo_path, storage_key, [{content_hash, vector}]}; QueryVectors{repo_path, storage_key, query_vector, top_k} → ranked (path,start,end,score). Drop/GetFragmentMetadataFromHash/Resync reused; Index/Resync orchestrated by the app. Cap CODEBASE_CHUNKS.
- App flow: Scan → diff manifest vs store → GetChunks for changed → embed in batches through crates/network_gate → StoreVectors → app-side status pushes. Search: embed query locally → QueryVectors. storage_key change → full re-embed.
- No-helper: same algorithm; `git ls-files -z` (find fallback), hashes from `git ls-files -s`/sha256sum, batched reads over the out-of-band executor, chunk locally; store app-side keyed by host_id+repo_path. Resync on AfterOwnWrite / Precmd after HEAD-changing git / user action. No timer.
- Reuse the local CodebaseIndexManager embedding+ranking with a pluggable fragment source (helper / shell / local) — read codebase_index_model.rs, codebase_index_store.rs first.
