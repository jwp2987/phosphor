# Round 14 wave 3b: app cases T26 to T30 (window use)

Owner 2026-11-10: "build out the tests". Source: `docs/design/r14-test-gaps.md` 7.1, wave 3, T26 to T30. Nothing was compiled or run.
The cases are in `script/realapp/appci/cases_window_use.py`, all in `cases.PROVING`. The per-case description is in `docs/testing.md`
("Round 14 wave 3: what a user does to the window").

## What the harness already had, and what was missing

| need | found | decision |
|---|---|---|
| window resize | `cases_ui.resize_to` (sway on the focused window, xdotool, System Events) | a `Window` class addressing sway by the app's pid, with capture / restore; macOS reuses `resize_to` |
| "the app's grid" for T26 | no log line: `TerminalView::resize_internal` (`app/src/terminal/view.rs`) resizes the model and emits `Event::Resize`; the pty gets `Message::Resize`, coalesced keep-last in `local_tty/event_loop.rs` `drain_recv_channel` | one trace-only line, `hop=grid_resize rows= cols= pane=`, logged on the main thread where the model is resized. `stty size` is the kernel's side; the two differ when the last resize of a burst is lost or reordered |
| pointer placed without OCR (T27) | `appci_find` (#1789) reports any drawn text, menu labels included; `cases_ui.FIND_RE` takes `\S+` tokens only | a reader for tokens with a space (`find_rows`); the app trims token-file lines and nothing else (`parse_tokens`) |
| tab titles (T28) | the hook attaches hits at layout time (`text_layout_system.rs` `attach_find_hits`), so a title laid out before its token was registered never reports | tokens are made and registered before the tabs are opened (own `open_tabs_tp`, which also records each shell's pid) |
| focus away and back (T29) | `cases.ref_terminal` and `RefTerm.switch` (none on Windows) | reused; Windows returns the focus by closing the reference |
| minimise (T30) | nothing | sway: workspace switched away; X11: `windowminimize`, or `windowunmap` with no window manager; macOS: `AXMinimized` |
| fullscreen (T30) | app binding F11 on Linux and Windows (`root_view.rs`), cmd-ctrl-f on macOS (refused by the harness guard) | F11 on Linux, `AXFullScreen` on macOS |

## Choices and what was rejected

- **T26 "final `stty size` equals the app's grid".** Rejected: logging at the pty side (`on_resize`): it would compare the kernel with
  itself. Rejected: a `stty size` between the copies of the reflow half: it adds a block, and the copy takes the newest block. The proof that a
  resize took is the hop (else a screenshot diff).
- **T27 stale positions.** The hook logs a token once per position. A menu entry is accepted only from a line written after the right click,
  and the two block menus open at different points of the token so the second is logged anew.
- **T28 which sighting is the tab.** The token of a tab is also drawn in its pane while that tab is shown. `pick_tab_spots` takes the topmost
  (bar) or leftmost (panel) sighting and refuses unless the set is one row in tab order, or a stacked column. A wrong pick cannot pass: the
  oracle is each tab's own `pwd` and its shell pid.
- **T29 on Windows.** The focus-reporting half is not run there (ConPTY delivers focus as console records). It is a note, not NOREF: the typing
  half is judged in full. Rejected: making every Windows row NOREF, which would read as "never judged".
- **T30 "first frame within the UI budget".** Two checks: a frame within 2 s of the show call (`hop=frame_drawn` time), and the largest
  main-thread item of the next 3 s within max(16 ms, 3 x the largest item of the same stream while shown). The absolute 4 ms budget alone would
  fail every software-rendered frame (`ui_item_metrics` says so), so the control is the same stream on the same renderer.
- **Never a skip after a check.** `run.py` turns a `Skip` into a skip row even when checks already failed. Each case skips only before its first
  check; later gaps are UNVERIFIABLE (self-test pins this).

## Risk

- App: one `log_hop` call behind `rows_or_columns_changed()`, free when input-order logging is off. No behaviour change.
- Tests: none has run. Likely first-run findings are listed in the report (X11 without a window manager, tab title text in the horizontal bar,
  sway workspace switch as "minimise", the 3 x control bound).
