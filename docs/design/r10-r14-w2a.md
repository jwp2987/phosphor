## What is built

## Evidence from the code that shaped each case

- **Provider wire (T12).** The fake model spoke only Ollama NDJSON (`fake_model.py`: `/api/chat`, `/api/show`, `/api/tags`). The app's Anthropic
  path is genai's adapter: `POST {base_url}messages` (`lib/rust-genai/.../anthropic/adapter_impl.rs:43`), headers `x-api-key` and
  `anthropic-version` (`adapter_shared.rs`, `build_web_request_data`), an event stream read by `streamer.rs` (`message_start`,
  `content_block_start` / `_delta` / `_stop`, `message_delta`, `message_stop`; tool input as `partial_json`). A base URL with only a host gets
  `/v1/` (`chat_stream.rs` `normalize_endpoint_url`). So the fake gained that wire on the same port, selected by the request path.
- **Keyring (T12).** A provider type other than Ollama waits for the keyring before it sends (`agent_providers/mod.rs`
  `must_wait_for_keys`). The macOS test session has no default keychain (`cases_agent_resilience.ENV_ERR_RE`). There the case reports `noref`
  with that reason instead of a failure of the wire.
- **Model switch (T11).** A typed `/model` opens the inline model selector (`terminal/input/slash_commands/mod.rs:996`); its rows are
  "<provider name> / <model name>" (`agent_providers/mod.rs` `build_byop_llm_infos`). The app logs `[byop] opening stream: model=<id>` per
  request (`chat_stream.rs:7682`), enabled in the Windows `RUST_LOG`. Both providers are Ollama-type so neither waits for a keyring; the "key"
  is an `extra_headers` sentinel, as `agent_gate_key_never_leaves` does.
- **Auto-run (T13).** `BlocklistAIPermissions::can_autoexecute_command` (`ai/blocklist/permissions.rs:925`): deny list first, then the safe
  read-only allow list (`safe_command_allowlist_enabled`, `ai/blocklist/safe_commands.rs`), then the profile, whose default is always-ask.
  The safe list is read from `settings.toml`, so it can be set with the app stopped on every platform. The profile's own regex lists live in
  a stored object that only the settings page edits. `hop=agent_action id= kind=run_shell_command status=` (`action_model.rs:764`) says
  `blocked` for a card and `running` / `done` for a run.
- **Resume (T14).** `/conversations` opens the inline conversation list, filtered by a fuzzy match on the TITLE
  (`terminal/input/conversations/data_source.rs`). A stored conversation is loaded and its blocks put back before the agent view is entered
  (`terminal/view/agent_view.rs` `enter_agent_view_for_conversation`). Every fake title was the same string, so the fake now answers a tagged
  title when the prompt names one. The only "blocks put back" line was a plain `log::info!`, which the Windows `RUST_LOG` hides.
- **Block context (T15).** The app attaches the blocks run since the last prompt in front of the prompt (`<attached_context>`, #2045). Outbound
  redaction is one choke point (`agent_providers/outbound_redaction.rs`). A copy honours hidden secrets only in the `asterisks` display mode
  (`terminal/model/grid/grid_handler.rs:1220`, `is_visually_obfuscated`), so the case sets that mode.

## Chosen design

- One module, pure judges with self-tests of the right and the wrong inputs (`selftest_agent_w2.py`).
- Settings are changed by stop, edit the profile file, start (`Settings`), the pattern `agent_restart_*` uses. A live edit works on Linux only.
- T12 calls the existing bodies of `agent_approval`, `agent_question_answer` and `agent_fault_disconnect` and adds one requirement: every chat
  request of the step arrived on the Anthropic wire (`fake.by_wire`).
- T13 sends the command to the model by a key ("run scripted command KEY"), never by typing shell syntax into the agent input.
- One app change, trace only: `hop=conversation_restored`.

## Rejected

- **Driving the settings page by keyboard** for the profile's allow and deny lists (T13) and the model (T11): several minutes per case, OCR
  needed, and the page is `settings_ui_toggle_persists`'s subject (T17).
- **A separate terminal-mode twin.** The scripted model runs only in the `agent@fake` pass (`run.py fake_pass_plan`; the self-test pins
  `PROVING_FAKE` to agent-only cases). A second fake pass is a cost decision for the coordinator and the owner.
- **Judging T14 by the conversation id alone.** The request content (earlier turn exactly once) is what the user's model sees; the id is a note.
- **A new fault set for the Anthropic wire** (`ask_*`). Only the faults T12 needs have an Anthropic form; the others answer 501, loudly.
- **`/auto-approve` in T13.** With the default `auto_approve_bypasses_command_denylist = true` a denied `rm` runs by design; testing that
  switch needs its own expectation table.

## Risk

- Nothing was run. Three UI assumptions come from reading only and the first run decides them: the model selector takes a typed name and Enter;
  the conversation list takes a typed title and Enter from the terminal view; block-up selects the `cat` block in an agent conversation.
  Each failure mode has its own message and screenshots.
- The Rust change adds a counter and a lazily formatted trace line; no state or control flow changes.
- `fake_model.py` changes are additive: the Ollama wire, `purpose_reply` without messages and every existing trigger answer as before
  (existing self-tests unchanged and green).
