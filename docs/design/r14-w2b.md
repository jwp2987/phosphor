## The two hops (app change, trace only)

Both go through `warpui::input_order::log_hop`, so they cost one `enabled()` check when input-order logging is off and are
visible on Windows without touching `WINDOWS_RUST_LOG`. Neither changes behaviour.

1. `hop=vtab_row_status view=<EntityId> status=<name>` (`app/src/workspace/view/vertical_tabs.rs`).
   `resolve_icon_with_status_variant` is the one place all three row layouts (pane row, compact row, summary) take a terminal
   row's icon from. The name is the status the badge shows: `ConversationStatus::hop_state_name()` for an agent row, `none`
   for an agent row with no badge, `no_agent` for a plain terminal. A row is rendered every frame, so the line is written
   only when the name changes for that view (a thread-local map, touched only while logging is on).
   `hop_state_name()` is new on `ConversationStatus`; `hop=turn` now calls it instead of its own inline `match` (same names).
   Tests: `vertical_tabs_tests.rs` `conversation_status_hop_names_are_the_ones_the_cases_read`,
   `row_status_name_follows_the_badge_the_row_draws`, `row_status_hop_has_a_fixed_format_and_logs_only_changes`.
2. `hop=osc52_clipboard op=<write|read> access=<deny|write_only|read_write> allowed=<bool>`
   (`Osc52ClipboardAccess::hop_detail` in `terminal/settings.rs`, called from the two `ModelEvent::Clipboard*` arms of
   `terminal/view.rs`). Test: `settings_tests.rs` `osc52_hop_detail_names_the_request_the_setting_and_the_outcome`.

Rejected: reading the badge colour from a screenshot (theme-dependent, needs Pillow); a plain `log::info!` (hidden by the
Windows `warn` base); logging the row status from the conversation model (that is `hop=turn`, which already exists and does
not prove the panel drew anything).

## The cases

Every case: typing at 10 to 25 ms per key with instant Enter, the exact received line checked (`rec.log`, PSReadLine history
in the PowerShell pane), a control that a wrong result trips, pure parts unit-tested in `selftest.py`.

### T16 `agent_hidden_tab_attention` (agent mode, fake-model pass; about 3 min)

Tab 2 asks the scripted model for a question with the `ask_slow` fault (the call arrives 12 s after the prompt). The case
switches to tab 1 at once and proves tab 1 answers. Then, with nothing typed:

- the ask action reaches `blocked` (`hop=agent_action`), and within 5 s a `hop=vtab_row_status ... status=blocked` line
  follows, logged AFTER the switch away: the row of the hidden tab shows the waiting state without the user touching anything;
- exactly one view went `blocked`, and none was `blocked` before the question (control: a hop that always or never says
  `blocked` fails one of the two);
- typing in tab 1 is exact (shell burst and one prose line to the agent) and does not answer the card (the ask is still open,
  the model got no tool result);
- tab 2's key, Enter: the ask is `done`, the model gets the answer, the turn ends `success`;
- back in tab 1 the same row leaves `blocked` and ends `success`.

Windows: runs when the profile already has vertical tabs on; otherwise SKIP naming the missing capability (the live settings
rewrite is not ported there).

### T17 `settings_ui_toggle_persists` (both modes; Linux, macOS; about 3 min)

Described in the table above. Checks: the settings key opened a tab (tab count from `hop=tab_activate`); after the two palette
actions exactly `appearance.vertical_tabs.enabled` and `appearance.text.font_size` differ in the file (flat key compare, any
other changed key fails by name); `stty size` moved after each; after a relaunch the file still holds both and the app runs
on them (font size down by keyboard writes old value + 0, not default - 1); hand edit seen (`stty size` moves); the bytes
put back are seen (`stty size` returns: #2026); the next app write does not resurrect the hand edit.

### T18 `osc52_write_read` (both modes; Linux, macOS, Git Bash; plus over ssh; about 2 min)

Write: `printf` of OSC 52 with a token, clipboard pre-set to a sentinel; the clipboard holds the token; hop `op=write
allowed=true`. Read: the clipboard is set to a second token; a raw-tty reader (`osc52_reader.py`) sends the OSC 52 query and
DSR 5; it must receive `ESC[0n`, no OSC 52 reply and no base64 of the token; hop `op=read allowed=false`. The expectation
follows the profile's `terminal.osc52_clipboard_access` (unset = write only), so an owner seed that sets it is judged by what
it says. Git Bash has no termios in the harness Python: the query is sent with `printf`, the hop is the verdict and an exact
burst right after proves no reply landed in the shell's input. Over ssh: the write and the query again from the remote shell.

### T19 `history_survives_restart` (both modes; all five; about 3 min)

Three commands, stop (quit key on Linux, stop by pid elsewhere), relaunch, the three recalls. An agent prompt (agent mode).
Three more commands, kill -9, relaunch, the three recalls. Each recall must make the shell receive exactly one line, equal to
the original. The shell's own history file holds each original at most once before the recalls, and never the agent prompt.

### T20 `restore_shows_history` (both modes; Linux, macOS, Git Bash; about 3 min)

`restore_session` on. A token printed by `printf '%s%s\n' A B` (the command text never holds the joined token), in agent mode
also one agent turn. Find matches both before the stop (precondition). Stop, relaunch: Find for the token gives
`result=scroll`; Find for a token never printed gives none (control); in agent mode Find for the conversation token gives
`result=scroll`; the effect file and `rec.log` show nothing re-ran.

## Risk

- The cases rest on reading, not on a run. The assumptions most likely to be wrong at first play: the palette row picked for
  "Increase font size" (a second row with the same text exists for notebooks), the inline history menu's behaviour with a
  typed prefix, and whether Find searches a restored agent conversation. Each is checked by a precondition that names itself
  in the failure text, so the first run gives a TEST-vs-APP verdict quickly.
- The Rust change is two log lines and one moved `match`. Not compiled.
