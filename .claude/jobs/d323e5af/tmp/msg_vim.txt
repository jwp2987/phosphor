feat(tui): add vim mode with modal editing and footer indicator

Ports warpdotdev/warp#71fafb46c (TUI vim mode) plus its shared-FSA
prerequisite. Reuses this fork's existing crates/vim infrastructure and both
GUI VimHandler implementors (CodeEditorView, EditorView/notebooks) rather
than building a third parallel implementation.

- crates/vim/src/vim.rs: continuous-replace (R) mode -- ReplaceChar/
  ReplaceText events, continuous_replace state, finish_replace_mode, and
  the new VimHandler::replace_text trait method. Both existing GUI
  implementors updated to match.
- app/src/code/editor/model.rs: vim_visual_selection_ranges, vim_replace_text,
  vim_select_to_line, vim_move_to_last_line, EOF-safe linewise selection math.
- New crates/warp_tui/src/input/vim.rs (640 lines): full VimHandler impl for
  TuiInputView. This fork's VimOperator has 7 variants, not upstream's 9
  (no Indent/Dedent) -- adapted includes_trailing_newline() to
  `*operator != VimOperator::Change` instead.
- crates/warp_tui/src/input/view.rs: owns a VimModel, routes input through
  the shared FSA when AppEditorSettings::vim_mode_enabled(); renders
  Visual-mode selection via editor_element.rs's selection_ranges: Vec<Range<..>>
  (replacing the old single-range sel_char_range field).
- terminal_session_view.rs footer: vim mode label (NOR/INS/VIS/V-L/REP) added
  as a new leading FooterSegment::Vim variant in the enum-based footer design
  (this port branched before the statusline work landed and originally used
  a struct-based FooterSegments; reconciled at merge time onto the
  already-committed enum design rather than keeping two competing footer
  architectures -- see merge note below).
- New /vim-mode slash command (SlashCommandKind::VimMode) flips the
  pre-existing cross-surface text_editing.vim_mode_enabled setting (no new
  setting needed), with a menu-row checkmark matching /auto-approve's
  state_suffix pattern.

Merge-time integration work (this port's worktree branched before 4 other
streams landed, so these needed real reconciliation, not just conflict
markers picked one way):
- static_commands/mod.rs: trivial additive conflict (VimMode alongside
  ApiKeys/Statusline in the same enum/match/supports_tui spots) -- kept all.
- terminal_session_view.rs footer: the substantive one. Kept the
  already-committed, already-tested enum-based FooterSegment/Vec<FooterSegment>
  design (added for configurable statusline ordering) and added
  FooterSegment::Vim(&'static str) to it, with an explicit
  (Vim, ShellMode | Model) => " " separator rule preserving this port's
  "plain space joins the leading vim/shell-model cluster" intent, rather than
  keeping vim mode's now-superseded parallel struct-based footer design.
- editor_element_tests.rs: 2 leftover sel_char_range references (from the
  earlier tab-indentation port, added independently on the other side of this
  merge) updated to the renamed selection_ranges: Vec<..> field -- a silent
  merge casualty git didn't flag as a conflict since the two edits were on
  different lines of the same file.
