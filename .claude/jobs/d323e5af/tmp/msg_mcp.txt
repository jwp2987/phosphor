feat(tui): surface MCP tool+server identity, render PR review comment threads

Ports two independent upstream features found via the ongoing warp/master
commit review.

- MCP tool + server identity (warpdotdev/warp#6cfb37da7): confirmation
  cards, transcript labels, and the warping indicator now show which MCP
  server a tool call came from, not just a generic tool name -- useful once
  a user has multiple MCP servers with similarly-named tools. Mostly wiring
  existing identity data through to the display layer: this fork already
  had server_id on AIAgentActionType::CallMCPTool and
  TemplatableMCPServerManager::get_mcp_name predating this work. New
  tool_call_label_with_server (tool_call_labels.rs) and
  mcp_blocked_title_text/mcp_viewing_detail_title_text
  (requested_command.rs) drive the per-surface text; tui_export gains
  mcp_server_name_for_id. Dropped the unrelated McpRequest/JSON-tree piece
  of the upstream diff -- this fork doesn't have that feature to extend.

- GitHub PR review comment threads in the TUI (warpdotdev/warp#157452cd5):
  new crates/ai/src/agent/action/review_comments.rs (ReviewCommentThreadItem
  trait, group_review_comment_threads, format_review_comment_thread) centralizes
  thread grouping/formatting shared by GUI and TUI -- this fork's existing
  InsertReviewComment/InsertedCommentLocation data model in crates/ai and
  app/src/code_review/comments/ was already byte-for-byte the same shape
  upstream's commit assumes, so this ported with no data-model reconciliation
  needed (unlike the GitRepoModels precedent from the original TUI port).
  app/src/code_review/comments/flatten.rs now calls the shared helper instead
  of its own hand-rolled grouping (-45 lines). New
  crates/warp_tui/src/tui_review_comments.rs renders each thread as Markdown
  with file:line target, author, body, and a linked GitHub URL.

Two merge-time integration fixes (both against just-landed sibling work,
neither a bug in this port itself):
- app/src/tui_export.rs, crates/warp_tui/src/tool_call_labels(_tests).rs:
  trivial additive merge conflicts against the API-key-management and
  chevron-pinning streams (both sides added distinct functions/tests at the
  same insertion point) -- kept both.
